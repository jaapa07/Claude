RepairXmlJson: corrige JSON e XML quebrados

Coloque este processor logo depois da ingestão (GetFile, ConsumeKafka, InvokeHTTP, ListenHTTP...) e antes de qualquer processor que leia JSON/XML (EvaluateJsonPath, JoltTransformJSON, ConvertRecord, EvaluateXPath, SplitXml...). Documentos válidos passam intactos; os quebrados são corrigidos.

Fluxo sugerido

[ingestão] → RepairXmlJson ─success→ RouteOnAttribute (repair.status) ─repaired→ [log/alerta]
                          │                                         └─valid/repaired→ [seu fluxo]
                          └─failure→ PutFile / PutS3 (quarentena para análise)

Atributos gravados

  • repair.status: valid (não mexeu), repaired (corrigiu), normalized (modo "Sempre normalizar" limpou um documento válido) ou failed.
  • repair.actions: lista das correções com contagem, ex.: aspas-extras-removidas(2),e-comercial-escapado(1).
  • repair.action.count, repair.format, repair.error, mime.type.

Observações

  • A saída é sempre UTF-8. A declaração XML é ajustada para encoding="UTF-8".
  • Números JSON são preservados exatamente como vieram (sem perda de precisão).
  • O conteúdo é carregado inteiro em memória: indicado para documentos de até algumas dezenas de MB.
  • A correção usa heurísticas. Revise periodicamente os FlowFiles com repair.status=repaired.
